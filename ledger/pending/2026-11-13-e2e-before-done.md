# 제안: '완료' 선언 전에 실제 원격 대상으로 e2e 검증을 돌린다

- 날짜: 2026-11-13
- 발견 위치: solstack 구축 세션 (OpenCode)
- 유형: pattern
- 반영 대상: `skills/patterns/e2e-before-done/SKILL.md` (신규)

## 근거 (세션에서의 실제 사건)

- 1: update-check 알림 로직 검증 시, 새 클론에서 바로 테스트하니 "정상 동작"처럼
  보였지만 실제로는 뒤처짐 케이스를 전혀 검증하지 않은 자기충족 테스트였음.
  이를 발견하고 원본에 커밋을 추가해 진짜 뒤처짐 경로를 검증했다.
- 2: push 후 GitHub Actions 첫 실행 결과까지 확인하는 습관이 반복됨
  (validate 워크플로우 녹색 확인 후 보고).

## 제안 내용

스크립트·자동화·인프라 작업은 "완료"라고 말하기 전에 다음을 순서대로 수행한다:
1) 성공 케이스와 실패/엣지 케이스를 구분해서 각각 트리거한다.
   (테스트 환경이 성공만 지나가는 경우를 의심한다 — 새 클론=항상 최신처럼)
2) 원격 시스템(GitHub, 배포 파이프라인)에 실제로 밀어 넣은 뒤 결과를 확인한다.
3) 검증이 끝나면 테스트용으로 만든 커밋/파일을 원격에 남기지 않고 정리 커밋으로 되돌린다.

## 기대 효과

"분명 잘 되는 것 같은데 실제에선 안 되는" 상태로 남는 것을 막고,
검증 흔적이 저장소 히스토리에 쌓이지 않게 한다.
